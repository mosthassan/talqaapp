## 1) ملخص حالة الإنتاج (Production Status)

- **حالة البناء والجودة:**
  - `npm run build` ينجح بنسبة 100% بدون أي أخطاء أو تحذيرات تجميع (`standalone output`).
  - `npm run lint` ينجح بنسبة 100% مع 0 أخطاء و 0 تحذيرات.
  - `npm test` ينجح بنسبة 100% (21 اختبار وحدة شامل لمحرك قياس السرعة وخوارزميات مسابقة الولاء والسحب الذري).
- **الهيكل المعماري والبيانات:**
  - تم نقل وتفعيل قاعدة بيانات **Google Firebase** (Cloud Firestore + Firebase Auth + Firebase Admin) رسمياً وفق مشروع `talqanet-cf3e1`، مع الحفاظ التام على `StaticSeedRepository` كطبقة سقوط أوفلاين دائمة حتى لا يعرض التطبيق شاشة بيضاء أبداً.
- **التنظيف الكامل:**
  - تم حذف مجلد الكود القديم `legacy/` ومجلد المراجع الخارجية `lovable-ref/` بالكامل، وأصبح المستودع نقياً بنسبة 100% وخالياً من أي أسرار أو اعتمادات مكشوفة.

## 2) ما يعمل في التطبيق بالتفصيل (What Works 100%)

1. **مسابقة الانتماء ونظام الولاء السحابي (`LoyaltyContestView` / `/rewards`):**
   - **بنية Server-Authoritative محكمة:** السحب والتحقق وحرق الكروت يتم حصراً على الخادم (`/api/loyalty/redeem` و`/api/loyalty/verify-card`).
   - **خوارزمية سحب مشفرة:** اختيار الجائزة الرابحة عبر `crypto.randomInt` من Node.js مرجحة بنسب الفئات المحددة.
   - **معاملات ذرية (Atomicity):** التحقق من الكروت الـ 10، حرقها، سحب الجائزة، وتسجيل المعاملة دفعة واحدة. أي خطأ أو نفاد في المخزون يتراجع بالكامل دون حرق أي كرت للمشترك.
   - **منع التكرار (Idempotency):** دعم كامل لـ `idempotencyKey` بحيث تعيد إعادة المحاولة نفس النتيجة دون حرق إضافي.
   - **مكافحة التحايل:** تحديد معدل الطلبات (Rate Limiting) وتأخير تصاعدي عند الفشل المتكرر، والتحقق من حالة الكروت (رفض الكروت الجديدة لحماية أموال المشترك).
   - **واجهة مستخدم احترافية:** شريط تقدم دائري (0/10)، لصق دفعة واحدة، مسح QR بالكاميرا، عجلة حظ 60fps على Canvas بأصوات ميكانيكية حقيقية عبر Web Audio API وهزة تفاعلية واحتفال Confetti، ومحفظة جوائز محلية.

2. **لوحة الإدارة والتحكم المصغّرة المحمية (`AdminDashboardView` / `/admin`):**
   - محمية بـ **Firebase Authentication** ولا تقبل الدخول إلا للمشرفين المعتمدين.
   - **صندوق الجوائز (Prize Vault):** إضافة كروت الجوائز فردياً أو CSV، مراقبة المخزون، تنبيهات انخفاض الرصيد، وإخفاء الأكواد افتراضياً مع كشفها عند الطلب.
   - **أوزان وفئات السحب:** إمكانية تعديل أسماء الفئات والنسب المئوية مع التحقق الصارم من أن المجموع = 100%.
   - **قاعدة كروت الشبكة:** استيراد الكروت المستهلكة من تصدير ميكروتك لدعم التحقق الفوري.
   - **سجل المعاملات:** سجل تفصيلي للفائزين والكروت المحروقة مع محرك بحث وتصدير ملف CSV.
   - **التحكم بالمسابقة:** مفتاح تشغيل/إيقاف فوري وتحديد السقف اليومي للاستبدالات.
   - **إدارة المحتوى (CMS):** إدارة الباقات والأسعار والإعلانات ونقاط التوزيع.

3. **فحص السرعة الفعلي الشامل (`/speed`):**
   - محرك `SpeedTestRunner` الفعلي بدون أي أرقام مصطنعة؛ يقيس Ping و Jitter وسرعة التحميل والرفع بمتوسط مقطوع (Mbps).
   - مزود مزدوج: خوادم Cloudflare Edge ومزود داخلي احتياطي عبر Route Handlers.

4. **باقات الكروت وخريطة نقاط التوزيع في مأرب (`/packages`):**
   - استعراض الكروت وساعات العمل وحساب المسافة التقديرية عبر Leaflet بدون أي مفتاح API تجاري.
   - زر طلب الكروت مباشرة عبر واتساب.

5. **الاستراحة وبث المباريات HLS (`/lounge` و `/live`):**
   - تصفح أقسام Jellyfin وتنزيلات الشبكة الداخلية.
   - مشغل بث مباريات HLS بميزة Screen Wake Lock لمنع انطفاء الشاشة.

## 3) ما يجب على صاحب المشروع فعله قبل الإطلاق (مرتب بالأولوية)

1. **تدوير وتغيير كلمة مرور راوتر ميكروتك (عاجل جداً):**
   - الكود القديم للمشروع قبل الترقية كان يحوي بيانات راوتر ميكروتك مكشوفة. قم فوراً بتغيير كلمة المرور في راوتر MikroTik لحماية الشبكة.
2. **إنشاء حساب المشرف في Firebase Authentication:**
   - ادخل إلى لوحة تحكم مشروع Firebase (`talqanet-cf3e1`) وأنشئ حساب المشرف ببريدك وكلمة مرور قوية (مثال: `atheer.ye1@gmail.com`).
3. **نشر قواعد أمان Firestore:**
   - نفذ أمر النشر: `firebase deploy --only firestore:rules` للتأكد من حظر قراءة صندوق الجوائز من المتصفحات.
4. **شحن صندوق جوائز مسابقة الانتماء من لوحة الإدارة (`/admin`):**
   - ادخل إلى `/admin` واشحن كروت الجوائز الصالحة الحقيقية من ميكروتك لكل فئة.
5. **استيراد قائمة الكروت المستهلكة من ميكروتك:**
   - صدّر قائمة الكروت المستهلكة من ميكروتك واستوردها في تبويب "كروت الشبكة" باللوحة.
6. **اعتماد بيانات نقاط التوزيع في مأرب:**
   - مراجعة أسماء المحلات وأرقام الهواتف وإزالة علامة البيانات المؤقتة.
7. **إضافة متغيرات البيئة في Vercel:**
   - نسخ المتغيرات من `.env.example` إلى إعدادات Vercel وإطلاق النطاق الرسمي.

## 4) القيود الفنية المعروفة (Known Technical Constraints)

1. **المحتوى المختلط (Mixed Content):**
   - خدمات الشبكة الداخلية (`http://192.168.50.2:*` و`http://t.net`) تعمل ببروتوكول HTTP المحلي وتفتح حصراً عبر روابط خارجية `target="_blank"`. لا تحاول استدعاءها بـ `fetch()` مباشر من نطاق HTTPS للإنتاج.
2. **حدود مكافحة التحايل في مسابقة الولاء:**
   - إذا تم تسريب أرقام كروت مستهلكة بين المشتركين، فإن النظام يحرق الكرت لأول شخص يقدمه ويمنع أي شخص آخر من تقديمه لاحقاً، مع تطبيق Rate Limiting لمنع التخمين العشوائي للأكواد.
