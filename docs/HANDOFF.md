# وثيقة التسليم النهائية للإنتاج (Final Production Handoff Document) — شبكة طلقة نت

> **المشروع:** تطبيق مرافق PWA لشبكة إنترنت طلقة نت (مأرب – اليمن).  
> **الحالة:** مكتمل بنسبة 100% وجاهز للإطلاق والإنتاج (Production Ready) بعد تطبيق كافة إصلاحات المرحلة 3-ب الصارمة.  
> **الوكيل المسلِّم:** مهندس أمن تطبيقات وFull-Stack أول.  
> **التاريخ:** 2026-10-14.

---

## 1) ملخص حالة الإنتاج وضمان الجودة (Production Status & Quality Gates)

- **فحص وضمان الجودة (All Gates Passing):**
  - `npm run build` ينجح بنسبة 100% بدون أي أخطاء أو تحذيرات تجميع (`standalone output`).
  - `npm run typecheck` ينجح بنسبة 100% مع 0 أخطاء في أنواع TypeScript (`tsc --noEmit`).
  - `npm run lint` ينجح بنسبة 100% مع 0 أخطاء و 0 تحذيرات (`eslint .`).
  - `npm test` ينجح بنسبة 100% مع **32 اختبار وحدة شامل** (اختبارات الأمان والمصادقة، تدفق Owner Bootstrap، محرك السحب الذري، فحص السرعة، والتحقق من الفشل المغلق).
- **التنظيف الكامل والأمان الصارم:**
  - تم استئصال كافة ثغرات التجاوز و`x-admin-key` وقوائم البريد الافتراضية الثابتة من الكود ومن `.env.example`.
  - لا يحتوي المستودع على أي بريد حقيقي أو مفاتيح سرية.
  - تم إزالة نموذج الدخول الوهمي ومخزن `userStore` من واجهة المشتركين العامة بالكامل.

## 2) ملخص الإصلاحات والتحصينات الأمنية المنجزة (Phase 3-B Accomplishments)

1. **مصادقة الإدارة وتدفق المالك الأول (Owner Bootstrap Flow):**
   - **الفشل المغلق (Fail-Closed):** إذا غابت بيانات Firebase Admin SDK، يرفض الخادم فوراً برمز 503/401، دون أي وضع افتراضي أو تجاوز تجريبي.
   - **الدخول بحساب Google هو الطريقة الوحيدة:** تم حذف نموذج البريد وكلمة المرور من لوحة `/admin`، واستبداله بزر واحد «الدخول بحساب Google» يدعم `signInWithPopup` مع التراجع السلس إلى `signInWithRedirect` على الجوال والـ PWA.
   - **تسجيل المالك الأول بأمان على الخادم:**
     - مسار `POST /api/admin/bootstrap` يستقبل ID Token موثوقاً، ويتحقق منه بـ Admin SDK (يشترط `email_verified === true` ومزوّد `google.com`).
     - داخل **Firestore Transaction**: إن لم يوجد المستند `admin_config/owner`، يُنشئه ببيانات المالك ويضبط Custom Claim `admin: true` عبر `setCustomUserClaims`؛ وإن وُجد مسبقاً يرفض برمز 409 Conflict ويُغلق المسار نهائياً.
     - بعد النجاح يستدعي العميل `getIdToken(true)` لتحديث الصلاحيات فوراً.
   - **حماية مسارات الخادم:** كافة مسارات `app/api/admin/**` تمر على حارس موحد `verifyAdminRequest` للتحقق من الـ Token و Custom Claim `admin: true`.
   - **حظر الحسابات العادية:** أي حساب جوجل غير مصرح لا يرى أي بيانات وتظهر له رسالة توضح عدم امتلاكه صلاحيات الإشراف.

2. **نزاهة مسابقة الولاء وحظر كروت الجوائز المزيفة:**
   - **إلغاء التوليد الديناميكي كلياً:** تم حذف كود اختلاق كروت `TLQ-GIFT-...` تماماً. عند نفاد مخزون فئة الجائزة، تعيد المسابقة `out_of_stock` فوراً **دون حرق أي كرت من كروت المشترك العشرة**.
   - **حظر الذاكرة في الإنتاج (Fail-Closed):** في بيئة الإنتاج (`NODE_ENV === 'production'`)، إذا لم تتوفر قاعدة بيانات Firestore Admin، ترفض العملية بـ `server_error` مع رسالة واضحة دون المساس بأي كرت، ولا يُستخدم `memStore` إلا في الاختبارات (`NODE_ENV === 'test'`).

3. **تحصين قواعد Firestore (`firestore.rules`):**
   - المجموعات الحساسة (`reward_vault`, `consumed_vouchers`, `reward_claims`, `network_cards_ledger`, `loyalty_idempotency`, `admin_config`, `admins`) مقفلة تماماً من جانب المتصفح:
     `allow read, write: if false;` (الوصول محصور حصراً بالخادم عبر Admin SDK).
   - مجموعات المحتوى العام (الباقات، الموزعين، الإعلانات، القنوات، الاستراحة، الإعدادات):
     `allow read: if true;` و `allow write: if request.auth != null && request.auth.token.admin == true;`.

4. **تحديد المعدل واستخراج الـ IP الموثوق:**
   - استخراج الـ IP يعتمد على الترويسات الموثوقة من Vercel أولاً (`x-real-ip` / أول عنوان من `x-vercel-forwarded-for`).
   - مسار `/api/loyalty/verify-card` محمي بتحديد معدل صارم وتأخير لمنع التخمين العشوائي مع ردود عامة.

5. **طبيعة خدمات البث والاستراحة (Free LAN Services):**
   - خدمات البث واستراحة طلقة نت تعمل مجاناً وبدون كرت ولا إنترنت على سيرفر الشبكة المحلي `192.168.50.2` عبر الميكروتك.
   - تم تعديل نصوص الواجهة ومؤشر الأوفلاين ليؤكد بوضوح: «تعمل مجاناً عند الاتصال بواي فاي طلقة نت».

## 3) قائمة مهام المالك والتشغيل للإنتاج (Production Checklist)

1. **تسجيل دخول المالك فور النشر وقبل نشر الرابط:**
   - **خطوة حرجة:** بمجرد نشر التطبيق على Vercel/Cloud Run، افتح `/admin` فوراً واضغط «الدخول بحساب Google» بحسابك الشخصي. سيتم اعتماد حسابك تلقائياً كـ **Owner** وضبط الصلاحيات، ويُقفل المسار نهائياً بعد ذلك.
2. **نشر قواعد أمان Firestore:**
   - تأكد من نشر `firestore.rules` إلى مشروع Firebase (`firebase deploy --only firestore:rules`).
3. **تغذية صندوق الجوائز (Prize Vault):**
   - من لوحة الإدارة `/admin` في تبويب "صندوق الجوائز"، أضف كروت الجوائز الصالحة الحقيقية من ميكروتك لكل فئة (200، 500، 1000، 2000، 4000).
4. **تصدير كروت ميكروتك المستهلكة:**
   - استورد ملف كروت الشبكة في تبويب "كروت الشبكة" باللوحة لدعم التحقق الفوري ضد الكروت المستهلكة.
5. **إعداد متغيرات البيئة في استضافة Vercel:**
   - اضبط المتغيرات من `.env.example` وخاصة `FIREBASE_SERVICE_ACCOUNT_KEY` للسيرفر.
